# 地面连续运动性能修复 · 0.3.18

本次针对首页地面在飞行后段增加绘制负担的问题；保留现有渲染分辨率、树冠/建筑模型、风车动画和逐帧阴影更新。

## 修改

- 树木实例按 20 × 20 世界单位分块；静态物体在分区内合并，避免一小部分进入视野就绘制整块地形。
- 合并材质时用线性色彩的顶点属性保留每个物体的颜色，减少分区后新增的材质切换。
- 每架风车的 57 个旋转部件合并为 1 个网格，保留旋转父节点。
- 阴影相机覆盖实际可见地面；静态物体的投影范围预先计算，只有完全落在可见地面之外的投影才跳过。屏幕外物体投到屏幕内的阴影仍保留。
- 平坦底面横向多余的 140 段减为 1 段，纵向 200 段色彩采样和 UV 映射不变。每块底面从 56,000 个三角形减为 400 个。
- 冻结静态局部变换、清理空节点。开始运动前预编译沿途材质，减少首次进入新地形时的编译停顿。
- 增加固定容量 600 帧的诊断数据，不随运行时长无限增长。

## 验证结果与限制

使用项目内真实 Three.js 几何、实例矩阵和视锥算法检查 11 个沿途位置。1280 × 800 桌面布局下，主画面和阴影的估计三角形提交量合计平均减少约 **64%**。

| 路程位置 | 修改前主画面 + 阴影 | 修改后主画面 + 阴影 |
| --- | ---: | ---: |
| 0 | 2,870,666 | 958,354 |
| 150 | 4,321,143 | 1,235,399 |
| 350 | 1,495,921 | 324,812 |

这不是浏览器 FPS 测试。测试替换了 WebGL/DOM；当前受限运行环境中浏览器未能启动，因此没有真实 GPU 帧时间和视觉截图。分区也会增加部分场景的绘制调用数，实际收益仍取决于用户设备的 GPU 与驱动，应以实机持续播放为准。

执行 `npm run test:terrain` 可复核：

- 合并前后完整保留三角形、几何位置/颜色统计和全部树木实例矩阵、颜色。
- 风车从 57 次网格提交变为 1 次，仍持续旋转。
- 横屏/竖屏下阴影视锥覆盖可见地面及向地面投影的屏外物体。
- 模拟 5 分钟持续播放，路程正确、节点数不增长、采样固定在 600 帧；隐藏标签不继续推进地面。

浏览器实际运行时，在控制台执行 `window.__aitchPerformance()` 可读取最近最多 600 帧的 FPS、P95 帧间隔、超过 25 ms 的帧数、CPU 提交耗时与 WebGL 资源数量。`submitMeanMs` 是 CPU 调用耗时，不是 GPU 耗时；FPS 包含页面实际得到的动画帧调度。持续播放不同地形后分别读取，可以继续定位设备上的瓶颈。
